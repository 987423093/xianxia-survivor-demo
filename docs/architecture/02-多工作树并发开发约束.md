# 02. 多工作树并发开发约束

这份文档描述当前仓库为了支持多模块并发开发而采用的 seam 划分。

## 1. 目录角色

### 1.1 长期维护目录

长期维护目录：

- `web-runtime/`：可运行内核与源码。
- `scripts/`：测试、部署、资源管线。
- `assets/`：资源 manifest、raw 资产、生成结果。
- `docs/`：当前真相源、记录层、归档层。
- `openspec/`：规格记录层。

### 1.2 本地 scratch 目录

本地 scratch 目录：

- `.worktrees/`
- `tmp/`
- `output/`
- `.superpowers/`

这些目录默认不提交；切分支、切 worktree、准备合并前先执行 `npm run clean:artifacts`。

## 2. 推荐并发边界

- 战斗玩法：`web-runtime/src/gameplay/*`
- 局外成长：`web-runtime/src/meta/progression/*`
- 洞府 UI：`web-runtime/src/ui/home/*`
- 启动与壳层：`web-runtime/src/bootstrap/runtime/*`
- 资源与资产：`web-runtime/src/resources/*`、`assets/*`、`scripts/*`
- 内容配置：`web-runtime/src/content-registry/*`
- 文档与规格：`docs/*`、`openspec/*`

目标是不同 worktree 尽量各改一条 seam，而不是都去碰 `main.js` 或单个大配置文件。

## 3. 当前热点控制

- `main.js` 只保留装配和桥接。
- `themes.js` 只保留静态数据；实际消费优先通过 `content-registry/index.js`。
- `ui-shell` 与 `asset pipeline` 已补充 contract，测试脚本优先围绕 contract 校验。

## 4. 日常流程

- 进入目标 worktree。
- 执行 `npm run clean:artifacts`。
- 仅修改当前 seam 对应目录。
- 至少执行：
   - `npm run config:check`
   - `npm run test:meta`
   - `npm run test:ui-assets`
   - `npm run test:mobile`
   - `npm run smoke`
- 浏览器验收：首页、更多页、图鉴页、战斗页。
