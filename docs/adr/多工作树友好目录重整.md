# ADR-0001: 采用 worktree 友好的仓库布局

## Status
Accepted

## Context
当前小游戏仓库已经把玩法代码拆到多个模块，但仓库根目录仍混有浏览器截图、手工验收产物、临时目录和系统垃圾文件。后续如果要并发开多个 `git worktree` 开发不同模块，这些临时产物会让每个工作树都很容易变脏，也会增加 cherry-pick、对比分支和脚本验收时的噪音。

同时，`web-runtime/src/main.js` 仍是最容易被多个方向同时修改的入口热点。移动端壳层、启动参数和模块装配混在一起，会放大多人并发改动时的冲突概率。

## Decision
采用以下仓库约束：

1. 把 `tmp/`、`output/`、`.superpowers/` 视为本地临时产物目录，不再纳入版本控制。
2. 在仓库根目录预留并忽略 `.worktrees/`，作为后续并发开发时的默认 worktree 落点。
3. 继续保持 `main.js` 只做装配；将 URL 启动参数和 UI 壳层逻辑抽到 `web-runtime/src/bootstrap/`，降低入口文件冲突面。
4. 用固定脚本清理临时产物，避免手工删除遗漏。

## Consequences

### Positive
- 分支和 worktree 默认更干净，减少截图、缓存和系统文件造成的无关 diff。
- 入口公共层更清晰，战斗、洞府、资产脚本并发修改时更少同时碰 `main.js`。
- 临时验证产物仍可继续生成，但默认停留在本地，不再污染版本库。

### Negative
- 以前已经提交到仓库的 `tmp/` 验证截图会被移除，历史截图不再通过 Git 持续保存。
- 调试流程需要接受“截图是本地产物，不是版本资产”的新约束。

### Neutral
- 后续如果需要长期保留验收素材，应另建正式文档资产目录，而不是回流到 `tmp/`。

## Alternatives Considered

### 继续保留 `tmp/` 截图进版本库
- 放弃原因：会让每个迭代分支都带上大量无关图片 diff，不适合 worktree 并发开发。

### 只写文档，不改目录和入口结构
- 放弃原因：没有真正解决 repo 脏状态和入口热点，后续多人并发仍会持续冲突。
