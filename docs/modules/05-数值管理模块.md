# 05. 数值管理模块

## 1. 目标形态

数值管理模块负责把局内战斗、突破升级、Boss 节奏、章节难度、局外材料和成长成本放到同一套节奏标准下管理。它不是单纯调几个常量，而是回答这些问题：

- 玩家多久第一次突破。
- 一局应该出现几次突破选择。
- 第一只 Boss 什么时候出现。
- 同战力玩家打 Boss 应该打多久。
- 每章每难度应该给多少材料，支撑几局升一次局外养成。

目标是让玩家保持割草爽感，同时减少过于频繁的升级暂停，避免“刚开始打几只怪就一直选卡”。

## 2. 当前实现

状态：MVP

当前已经接入 `xianxiaTheme.balance`，修仙主题的核心节奏可以集中调整；`office`、`cat` 没有 `balance` 配置时继续走旧主题兜底。

当前能力：

| 数值面 | 当前实现 |
| --- | --- |
| 初始升级门槛 | `balance.xpCurve.base = 90` |
| 小怪经验 | 山魈小妖经验从 `12` 调整为 `9` |
| 精英经验 | 黑袍魔修经验从 `30` 调整为 `26` |
| 升级曲线 | `xpRequiredForLevel(level)` 读取 `balance.xpCurve` |
| Boss 出场 | 四章 Boss 目标时间为 `90 / 110 / 130 / 150` 秒 |
| Boss 血量 | `bossHpForChapter()` 读取 `balance.bossTargets.chapterBossHp` |
| 难度节奏 | `difficultyPacing` 影响 Boss 出场和 Boss 血量 |
| 材料产出 | `calculateRunRewards()` 读取 `balance.rewardFormula` |
| 奖励来源 | `calculateRewardSourceBreakdown()` 拆分击杀、闭关、Boss、倍率和额外来源 |
| 局外成本 | `upgradeCost()` 读取 `balance.upgradeCosts` |
| 调试快照 | `window.demoGame.snapshot().balance` 输出当前数值配置和跑测指标 |

已解决的核心问题：

- 初始 `nextXp = 36` 已改为修仙主题首级 `90`。
- 小怪经验已从 `12` 降到 `9`。
- 第一章 Boss 已从 `58 秒` 延后到 `90 秒`。
- 首次升级时间、Boss 出场时间、Boss 击杀时间、Boss TTK 已进入快照指标。
- 结算页已能展示材料来源明细，方便观察奖励公式是否符合预期。

## 3. v1 节奏目标

第一版先按 5-7 分钟一局设计，后续再按章节拉长或压缩。

| 指标 | 目标值 | 说明 |
| --- | --- | --- |
| 首次升级 | 开局 25-35 秒 | 让玩家先体验移动、攻击、拾取 |
| 前中期升级间隔 | 40-55 秒 | 选择有节奏感，但不频繁打断 |
| 后期升级间隔 | 60-80 秒 | 后期更多靠 build 成型和 Boss 压力 |
| 第一章 Boss 出场 | 约 90 秒 | 玩家至少拿到 1-2 次突破后见 Boss |
| 后续章节 Boss 出场 | 110 / 130 / 150 秒 | 章节越后越需要铺垫压力 |
| 同战力 Boss 击杀时间 | 45-75 秒 | Boss 有存在感，但不拖沓 |
| 单局目标时长 | 5-7 分钟 | 当前 Demo 的主循环长度 |
| 单局升级次数 | 6-9 次 | 避免 15 次以上高频暂停 |

## 4. 管理范围

### 4.1 局内修为

局内修为决定升级频率，优先级最高。

需要统一管理：

- 敌人经验值。
- 拾取物经验值。
- 初始升级门槛。
- 每级升级曲线。
- 局外天赋、功法、设施提供的经验倍率。
- 拾取范围对实际经验获取速度的影响。

第一轮调参建议：

| 项 | 当前 | 建议 |
| --- | --- | --- |
| 初始升级门槛 | 36 | 90 左右 |
| 小怪经验 | 12 | 8-10 |
| 精英经验 | 30 | 22-28 |
| Boss 经验 | 120 | 保持高奖励，但不连续触发多次升级 |
| 升级曲线 | `nextXp * 1.32 + 16` | 配置化，例如 `base=90, growth=1.38, flatAdd=28` |

### 4.2 战斗强度

战斗强度决定玩家清怪速度和 Boss 击杀时间。

需要统一管理：

- 玩家基础伤害。
- 法术伤害、冷却、数量、范围。
- 装备和本命法宝的伤害倍率。
- 普通怪、精英怪、Boss 血量。
- 章节和难度对血量、伤害、速度的倍率。

Boss 血量不再直接拍数值，后续按下面公式反推：

```text
Boss 目标血量 = 预期玩家 DPS * 目标击杀秒数 * 战斗修正系数
```

战斗修正系数用于考虑走位、Boss 无敌窗口、玩家攻击损失、阶段技能打断等情况。第一版可取 `0.85-1.15`，跑测后再修。

### 4.3 刷怪压力

刷怪压力决定单位时间经验和危险程度。

需要统一管理：

- 波次开始时间。
- 刷怪间隔。
- 场上数量上限。
- 普通怪与精英怪比例。
- Boss 出现前后的妖潮强度。

刷怪调参不能只看“怪多不多”，还要看每分钟经验产出。否则怪一多，升级频率又会失控。

### 4.4 Boss 节奏

Boss 是章节验收点，数值管理要定义：

- Boss 出场时间。
- Boss 目标击杀时间。
- Boss 阶段血线。
- Boss 技能冷却。
- Boss 技能伤害。
- Boss 击败奖励。

第一版目标：

| 章节 | Boss 出场目标 | Boss 击杀目标 |
| --- | --- | --- |
| 云栖竹谷 | 90 秒 | 45-60 秒 |
| 玄石古阵 | 110 秒 | 50-65 秒 |
| 血煞荒原 | 130 秒 | 55-70 秒 |
| 雷劫天门 | 150 秒 | 60-75 秒 |

### 4.5 局外经济

局外经济决定玩家刷几局能升一次天赋、法宝、功法或设施。

需要统一管理：

- 每局灵石、道行、玄铁、灵蕴、雷纹产出。
- 首通奖励与重复刷图奖励。
- 局外升级成本。
- 高难度收益倍率。
- 缺材料时推荐章节。

第一版不做复杂经济模拟，但文档和跑测要记录：

- 凡境通关一局能升几次低级天赋。
- 玄境通关一局能否稳定获得关键材料。
- 天境是否提供明显更高收益，而不是只提高难度。

## 5. 建议数据结构

当前在 `xianxiaTheme` 下已经增加 `balance` 配置块。

```js
balance: {
  runTargets: {
    firstUpgradeSeconds: [25, 35],
    earlyUpgradeInterval: [40, 55],
    lateUpgradeInterval: [60, 80],
    targetRunSeconds: [300, 420],
    targetUpgradeChoices: [6, 9]
  },
  xpCurve: {
    base: 90,
    growth: 1.38,
    flatAdd: 28,
    minEnemyXp: 8,
    eliteXp: 24,
    bossXp: 120
  },
  bossTargets: {
    defaultTtkSeconds: [45, 75],
    chapterBossAt: {
      "cloud-bamboo-valley": 90,
      "stone-array": 110,
      "blood-wasteland": 130,
      "thunder-gate": 150
    }
  },
  rewardTargets: {
    targetLowTierUpgradeRuns: [1, 2],
    targetMidTierUpgradeRuns: [2, 4],
    targetHighTierUpgradeRuns: [4, 7]
  }
}
```

`main.js` 已增加：

| 方法 | 作用 |
| --- | --- |
| `xpRequiredForLevel(level)` | 根据配置计算升级所需修为 |
| `getBalanceConfig()` | 读取当前主题的数值配置 |
| `recordBalanceMetric(key, value)` | 记录跑测指标 |
| `getBalanceSnapshot()` | 输出当前局数值快照，供调试和 Playwright 使用 |
| `calculateRewardSourceBreakdown(rewards)` | 输出结算奖励来源拆分 |

## 与其他模块的关系

- 核心割草战斗模块负责玩法执行，数值管理模块负责节奏目标和参数口径。
- 境界与局内升级模块负责突破表现，升级频率由数值管理模块约束。
- 法术和局内装备模块负责 build 差异，伤害和冷却最终要回到目标 DPS 区间。
- 章节、难度与 Boss 模块负责内容和机制，Boss 出场和击杀时间由数值管理模块校准。
- 材料与经济系统负责货币闭环，产出和成本目标由数值管理模块给出。

## 当前缺口

- 还没有自动战斗模拟器，只能通过浏览器和手动跑测记录节奏。
- Boss 血量已有目标配置，但还没有按真实玩家 DPS 自动反推。
- 刷怪压力仍主要由 `waves[]`、`spawnMods` 和难度倍率共同决定，尚未做每分钟经验产出模拟。
- 结算来源明细已经展示，但还没有沉淀成自动化数值验收数据。

## 后续计划

### P0：跑测校准

- 用凡境第一章跑测首次升级时间、5 分钟升级次数和 Boss TTK。
- 根据实测结果微调 `xpCurve`、小怪经验和 Boss 血量。
- 检查升级暂停次数是否稳定在 6-9 次。

### P1：建立自动化数值验证

- 增加只读数值断言脚本，验证首级修为、Boss 时间、经验值、成本公式。
- 增加 debug 入口，能快速模拟修为获取和 Boss 击杀记录。
- 记录每章凡境、玄境、天境的 Boss 出场和击杀时间。

### P2：经济表现补齐

- 将结算来源明细沉淀为数值跑测记录。
- 缺材料时在升级入口旁提示推荐章节。
- 根据实际跑测继续调局外升级成本。

## 验收标准

- 首次升级不早于 25 秒，且不晚于 35 秒。
- 第一章 Boss 约 90 秒出现。
- 第一章凡境同战力 Boss 击杀耗时在 45-60 秒。
- 5-7 分钟单局升级选择次数控制在 6-9 次。
- 调参时不需要到处搜索硬编码，核心节奏能从 `balance` 配置或文档定位。
- 玩家能从局外经济感知“这一局刷出来的材料能推进什么成长”。
