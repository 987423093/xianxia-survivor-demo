# 02 核心割草战斗

## 目标形态

核心战斗模块负责“爽感底盘”：玩家移动、敌人围攻、自动攻击、爆怪、拾取、升级、死亡和重开。它不应该绑定某个主题，修仙、打工人、猫猫都应该能复用。

目标体验：

- 进入战斗 5 秒内就有密集目标和自动攻击反馈。
- 玩家主要操作是走位，攻击自动发生。
- 每次击杀、拾取、升级、受击都有明显反馈。
- 一局失败后能快速重开或回洞府成长。

## 当前实现

状态：已完成

当前能力：

- 键盘和移动端虚拟摇杆移动。
- 镜头跟随玩家。
- 敌人从屏幕外生成并追踪玩家。
- 玩家接触敌人会受伤，有无敌时间。
- 自动武器按冷却索敌攻击。
- 经验珠和回血丹掉落。
- 经验满后弹出升级三选一。
- 死亡后进入结算页。

主要函数：

| 函数 | 作用 |
| --- | --- |
| `resetGame()` | 初始化单局状态 |
| `updatePlayer()` | 玩家移动 |
| `updateWaves()` | 刷怪波次 |
| `spawnEnemy()` / `spawnEnemyAt()` | 生成敌人 |
| `updateEnemies()` | 敌人移动和接触伤害 |
| `updateWeapon()` | 武器攻击循环 |
| `damageEnemy()` | 敌人扣血与死亡 |
| `gainXp()` | 获取经验并触发升级 |
| `finishRun()` | 死亡或结束结算 |

## 数据结构

单局核心状态在 `game` 对象中：

| 字段 | 用途 |
| --- | --- |
| `state` | playing / paused / upgrading / home / ended |
| `time` | 本局时间 |
| `killCount` | 击杀数 |
| `player` | 玩家属性 |
| `weapons` | 当前武器状态 |
| `enemies` | 敌人数组 |
| `projectiles` | 子弹数组 |
| `pickups` | 拾取物数组 |
| `particles` / `texts` | 反馈效果 |
| `runStats` | 本局统计，用于结算 |

数值节奏说明：

- 刷怪密度、击杀经验、升级频率和 Boss 出场时间后续统一受 [13-数值管理模块.md](./13-数值管理模块.md) 约束。
- 核心战斗模块只负责执行移动、攻击、掉落、受击和结算，不直接决定“多久升级一次、多久见 Boss”。

## 交互设计

- 操作层：移动优先，攻击自动。
- 压力层：敌人从四周包围，玩家通过走位拉扯。
- 奖励层：击杀掉经验，拾取后推动突破。
- 暂停层：升级选择时战斗暂停，选择后继续。
- 结束层：失败也给材料，保证局外成长。

## 当前缺口

- 没有正式的新手引导。
- 没有局内小地图或危险提示。
- 敌人类型还少，主要靠数量制造压力。
- 伤害统计和来源统计还没展示。

## 后续计划

- 增加冲刺/闪避。
- 增加更多怪物行为。
- 增加局内事件，例如灵泉、宝箱、妖潮。
- 增加战斗结果评分和最强法术统计。

## 验收标准

- 玩家可移动，镜头跟随。
- 敌人能持续生成并追击。
- 自动攻击能击杀敌人。
- 击杀会掉经验，经验能触发升级。
- 玩家死亡后进入结算，能重开。
