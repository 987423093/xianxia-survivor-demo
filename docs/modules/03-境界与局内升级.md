# 03 境界与局内升级

## 目标形态

这个模块把传统 `Lv.` 成长改成修仙境界成长，让玩家每次升级都感觉是在突破，而不是普通数值升级。

目标体验：

- UI 显示“炼气一层、筑基三层”这类修仙表达。
- 大境界变化时，人物形象、光效和反馈都明显变化。
- 升级选择不是普通按钮，而是“突破机缘”卡牌。

## 当前实现

状态：已完成

境界线：

1. 炼气
2. 筑基
3. 金丹
4. 元婴
5. 化神
6. 炼虚
7. 合体
8. 大乘
9. 渡劫
10. 飞升

当前能力：

- `realmLabel(level)` 把等级转成境界和层数。
- `realmIndex(level)` 决定当前境界图。
- 10 张主角境界图已经接入。
- 晋升时触发突破光效、环形冲击波、文字浮现。
- 升级 UI 使用三张机缘卡。

## 数据结构

主题字段：

| 字段 | 用途 |
| --- | --- |
| `realms` | 境界名称数组 |
| `heroRealms[]` | 每个境界的图片、光效颜色、光效风格 |

局内字段：

| 字段 | 用途 |
| --- | --- |
| `game.player.level` | 当前等级 |
| `game.player.xp` | 当前修为 |
| `game.player.nextXp` | 下一级所需修为 |
| `game.breakthroughFx` | 突破或装备变化特效 |

## 交互设计

- 击杀和拾取修为推动经验条。
- 修为满后打开“突破机缘”。
- 选择机缘后继续战斗。
- 大境界变化要强反馈，小层数变化轻反馈。
- 升级频率由 [13-数值管理模块.md](./13-数值管理模块.md) 约束，避免频繁弹卡打断割草节奏。

## 当前缺口

- 大境界突破没有额外条件。
- 大境界之间主要是视觉差异，数值差异还不强。
- 飞升没有终局特殊处理。

## 后续计划

- 增加境界突破条件，例如击杀数、Boss 击败、材料。
- 每个大境界给固定被动。
- 飞升后触发终局大招或结算倍率。

## 验收标准

- 等级显示不出现 `Lv.`。
- 晋升后人物基础图变化。
- 装备叠加不遮挡境界主体。
- 升级卡选择后能立即生效。
