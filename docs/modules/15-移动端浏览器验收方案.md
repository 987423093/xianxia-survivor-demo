# 15 移动端浏览器验收方案

## 目标形态

这个方案用于约束移动端页面验收，避免后续 AI 只跑静态检查就声称“已验证”。目标是让每次涉及竖屏布局、洞府移动端流、按钮皮肤、背景切换的改动，都有一致的浏览器级验收步骤。

## 当前结论

状态：MVP

当前项目的移动端验收原则：

- `npm run smoke` 只证明资源和静态路由能打开，不等于移动端交互已验收。
- 涉及 `demo/styles.css`、`demo/index.html`、`demo/src/main.js`、`demo/src/home/*`、`demo/src/theme.js`、`demo/assets/xianxia/*` 的改动，必须做浏览器级手机竖屏验证。
- 优先使用 Codex 的 in-app browser 打开本地页。
- 如果当前会话没有暴露 Browser 控制工具，再退回本机 Playwright 或同等本地浏览器自动化。
- 如果自动化点击被页面浮层、动画或遮挡元素拦截，允许临时用 DOM `click()` 完成状态切换，但必须把它记为交互风险，而不是假装真实点击没问题。

## 标准流程

### 1. 先跑基础脚本

在仓库根目录执行：

```bash
npm run test:mobile
npm run smoke
```

如果改动涉及 image2 资源，还要执行：

```bash
npm run assets:prepare
npm run assets:check
```

通过标准：

- `test:mobile` 通过，说明移动端壳结构、关键样式钩子、关键资源存在。
- `smoke` 通过，说明本地静态服务、主模块和关键资源没有断。
- `assets:check` 通过，说明背景图和图标尺寸、alpha 正常。

### 2. 起持续服务，不用临时 smoke 服务代替

执行：

```bash
npm run demo
```

默认地址：

```text
http://127.0.0.1:6273/
```

原因：

- `smoke` 会自己临时拉服务，只适合静态可达性检查。
- 浏览器验收必须依赖一个持续运行的本地服务，方便反复切换洞府、战斗和调试态。

### 3. 首选 in-app browser

如果当前会话已经暴露 Browser / in-app browser 控制能力：

- 直接打开 `http://127.0.0.1:6273/`
- 视口切到手机竖屏，建议 `390x844`
- 在这个浏览器里完成下面的状态验收

如果当前会话没有暴露 Browser 控制工具：

- 允许改用本机 Playwright
- 优先用仓库外已有运行时，不要先引入新的测试依赖
- 验收结束后要在回复里明确说明本次用的是 Browser 还是 Playwright

## 必验状态

### A. 洞府首页

入口：

- 打开首页
- 进入洞府

检查点：

- 手机态默认落在“首页卡片流”，不是旧桌面横排 Tab 总览。
- `首页 / 构筑 / 悬赏 / 章节 / 更多` 导航可见。
- 首页卡片里的主按钮已经挂到按钮底图，不再是纯 CSS 圆角框。
- `#homePanel` 上的 `--home-section-bg` 对应首页背景图，而不是空值。

### B. 更多页

入口：

- 洞府首页点击 `更多`

检查点：

- `更多事务` 标题出现。
- 背景切到 `more` 对应图，而不是仍停在首页图。
- 材料、图鉴、成长、存档工具等内容收进 `更多`，没有重新外露回首页。

### C. 图鉴页

入口：

- 从 `更多` 进入 `Boss 图鉴`

检查点：

- 标题为 `Boss 图鉴`
- `#homePanel` 当前背景切到 `bestiary` 对应图
- 不能继续误用 `chapters` 横幅

### D. 战斗页

入口：

- 从洞府开局进入战斗

检查点：

- 竖屏下主 HUD 是紧凑版，不是桌面布局硬缩放。
- `成长` 能拉起底部抽屉。
- 抽屉打开时，Boss 条、底部状态条和主按钮不发生明显遮挡。
- `洞府` 返回入口可正常工作。

## 推荐调试路径

如果只想快速验证关键状态，按下面顺序：

1. 首页打开洞府，验证首页卡片流。
2. 点 `更多`，验证更多页背景和分组入口。
3. 从更多页进 `Boss 图鉴`，验证图鉴背景。
4. 回到首页后开局，验证战斗页成长抽屉。

## 自动化读取口径

浏览器自动化除了截图，还应读取以下信号：

- `#homePanel.dataset.mobileSection`
- `#homePanel.dataset.homeVisual`
- `#homePanel.dataset.mobileMoreTab`
- `#homePanel.style.getPropertyValue("--home-section-bg")`
- 关键按钮的 `background-image`

这几项比单纯截图更稳，适合判断“状态切换了没”和“按钮底图是否真的接上”。

## 不合格的验收方式

以下方式都不能单独算“移动端已验收”：

- 只跑 `npm run smoke`
- 只看静态 HTML/CSS diff
- 只看资源文件是否存在
- 只在桌面宽度打开页面
- 只让自动化读 DOM，不看截图或真实视觉结果

- `test:mobile` 通过

- 战斗页存在移动端成长抽屉
