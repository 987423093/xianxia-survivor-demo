# `demo/src/main.js` 拆分计划

## 1. 目的

当前 `demo/src/main.js` 已经同时承担启动、资源加载、战斗循环、HUD、洞府 UI、局外成长、章节/材料/图鉴/悬赏、调试入口等职责，文件规模已经超过单文件可维护区间。

当前观测：

- 文件规模：约 `7787` 行，约 `323 KB`
- 直接结果：
  - 阅读成本高，定位逻辑慢
  - 移动端改动容易牵动战斗和洞府两侧
  - 调试入口和 UI 渲染混在一起，回归风险高
  - 资源加载策略难以单独优化

这份文档只定义拆分方案，不包含具体实现代码。

## 2. 拆分目标

目标不是做“漂亮的架构重写”，而是把 `main.js` 拆到几个可持续维护的边界：

- 单个模块职责单一，读文件时不需要同时理解战斗、洞府、调试三套上下文
- 战斗主循环、洞府 UI、资源加载、局外成长彼此解耦
- 后续做移动端优化、资源预热、图标补全时，不再需要反复触碰超大主文件
- 拆分过程中不改玩法、不改数值、不改默认桌面行为

约束：

- 继续使用原生 ES module，不引入新框架
- 保留 `theme.js` 作为配置中心
- 保留 `window.demoGame` 对外调试接口
- 拆分期间每一步都必须可运行，不能先大爆炸式迁移

## 3. 建议拆分边界

### A. 启动与资源层

建议目录：

- `demo/src/bootstrap/`
- `demo/src/assets/`

职责：

- URL 参数解析
- `canvas` / `ctx` 初始化
- `resize()`
- 资源 URL 选择、`webp` 优先、图片加载、预热、缓存
- 启动加载层与分组加载状态

建议模块：

- `bootstrap/runtime.js`
  - 解析查询参数
  - 初始化 UI 引用
  - 启动入口 `bootGame()`
- `assets/image-loader.js`
  - `loadImageAsset`
  - `getAsset`
  - `getAssetMeta`
  - `optimizedAssetFile`
  - `assetFileCandidates`
- `assets/preload-groups.js`
  - `boot-critical`
  - `run-critical`
  - `home-on-demand`
  - `background-idle`

### B. 战斗运行时

建议目录：

- `demo/src/gameplay/`

职责：

- `game` 运行时状态
- `resetGame()`
- `update()` 主循环
- 玩家、敌人、武器、投射物、拾取物、Boss、事件更新
- 胜负与结算触发

建议模块：

- `gameplay/state.js`
  - `game` 对象
  - `createRunStats`
  - `cloneWeapons`
  - `createEquipmentState`
- `gameplay/player.js`
  - 移动、冲刺、受伤、拾取
- `gameplay/enemies.js`
  - `spawnEnemy`
  - `spawnEnemyAt`
  - 敌人更新
- `gameplay/boss.js`
  - Boss 运行时
  - 预警、危险区、阶段处理
- `gameplay/weapons.js`
  - 武器冷却、发射、伤害结算
- `gameplay/events.js`
  - 奇遇、试炼、奖励掉落
- `gameplay/run-flow.js`
  - 开局、暂停、死亡、结算

### C. 渲染层

建议目录：

- `demo/src/render/`

职责：

- 所有 canvas 绘制
- 所有 sprite 几何兜底
- HUD 动态文本更新以外的画面渲染

建议模块：

- `render/world.js`
  - 地图、地面、背景
- `render/entities.js`
  - 玩家、敌人、投射物、拾取物
- `render/effects.js`
  - 文本飘字、粒子、突破特效、镜头震动
- `render/joystick.js`
  - 触控摇杆绘制

注意：

- `updateUi()` 不放进这里。DOM HUD 和 canvas 渲染是两类边界，必须分开。

### D. HUD 与浮层

职责：

- 顶部 HUD

- Boss 血条

## 4. 推荐拆分顺序

按风险最低顺序拆，不要从战斗主循环开始劈。

### 第 1 波：只拆纯工具和资源层

目标：

- 不碰核心玩法
- 优先减轻 `main.js` 体积

顺序：

1. 抽 `assets/image-loader.js`
2. 抽 `bootstrap/runtime.js` 的 URL 参数和 UI 引用
3. 抽 `debug/query.js`

验收：

- `npm run config:check`
- `npm run smoke`
- 默认主题和旧主题可开

### 第 2 波：拆 DOM UI，不拆战斗循环

目标：

- 把最臃肿的 `render*Tab`、HUD、overlay 从主文件搬走

顺序：

1. 抽 `ui/hud/status-bar.js`
2. 抽 `ui/overlay/*`
3. 抽 `ui/home/shell.js`
4. 抽 `ui/home/tabs/*`

验收：

- 洞府九页签可切换
- 结算页、暂停页、升级页、奇遇页行为不变
- 移动端竖屏截图回归通过

### 第 3 波：拆局外状态与奖励计算

目标：

- 把“算数”和“渲染”分开

顺序：

1. 抽 `meta/state.js`
2. 抽 `meta/progression.js`
3. 抽 `meta/rewards.js`

验收：

- `npm run test:meta`
- 结算来源明细和材料页逻辑不回退
- 存档导入导出不坏

### 第 4 波：拆战斗运行时

目标：

- 最后再动主循环，避免一开始就把风险拉满

顺序：

1. 抽 `gameplay/player.js`
2. 抽 `gameplay/weapons.js`
3. 抽 `gameplay/enemies.js`
4. 抽 `gameplay/boss.js`
5. 抽 `gameplay/events.js`
6. 最后抽 `gameplay/run-flow.js`

验收：

- `npm run smoke`
- Boss debug 路由可用
- 战斗、暂停、重开、结算主流程无回退

### 第 5 波：整理 debug API

目标：

- 给后续移动端优化和截图基线留稳定入口

顺序：

1. 抽 `debug/scenarios.js`
2. 抽 `debug/api.js`
3. 统一 `window.demoGame` 导出面

验收：

- 现有 URL debug 参数全部可用
- `window.demoGame.snapshot()` 与现有调试接口不丢

## 5. 明确不要做的事

- 不在拆分时顺手改数值
- 不在拆分时顺手重写 theme 配置
- 不在拆分时顺手改图片资源命名
- 不在拆分时引入 TypeScript、状态管理库或 UI 框架
- 不把“拆文件”升级成“架构翻新”

## 6. 模块边界规则

拆分时必须遵守这些边界，否则文件会换个目录继续膨胀：

- `ui/home/*` 只能做 HTML 组装、点击行为和页签切换，不做奖励计算
- `meta/*` 只做局外状态、奖励、升级和解锁，不直接操作 DOM
- `gameplay/*` 只操作运行时状态，不直接操作洞府 UI
- `render/*` 只负责 canvas 绘制，不更新 DOM
- `debug/*` 不承载业务逻辑，只拼装已有能力的调试入口

## 7. 验收标准

拆分完成后，至少满足：

- `main.js` 退化为应用装配入口，而不是业务全集
- `main.js` 控制在 `800-1500` 行级别以内
- 单个 tab 渲染文件、单个战斗子模块文件尽量控制在 `400-800` 行以内
- 任何人找“材料结算”“Boss 逻辑”“洞府章节页”“资源预热”时，不需要翻完整个主文件
- 现有脚本全部通过：
  - `npm run config:check`
  - `npm run test:meta`
  - `npm run smoke`
  - `npm run assets:check`

## 8. 建议任务拆法

如果后面要安排多人或分批执行，建议直接按下面拆：

1. 任务 A：资源加载与启动层
2. 任务 B：HUD 与 overlay
3. 任务 C：洞府 shell 与 tabs
4. 任务 D：局外 state / rewards / progression
5. 任务 E：战斗 runtime
6. 任务 F：debug 场景与 `window.demoGame`

其中 A、B、C、D 可以先并行设计，但真正动代码时要按顺序合。

## 9. 结论

`main.js` 的问题不是“代码写得差”，而是它已经承载了太多系统。最稳妥的做法不是一刀切重构，而是：

- 先拆资源和 UI
- 再拆局外状态
- 最后拆战斗主循环

这样能最大程度降低回归风险，也最适合你后面安排分批拆分。
